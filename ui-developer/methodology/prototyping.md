# Prototyping and iteration

Prototype to answer a question. Choose fidelity based on the risk being tested.

## Pick the smallest useful prototype

- Use content outlines or flows to test information order.
- Use wireframes to compare structure and density.
- Use a visual slice to test typography, palette, surfaces, and imagery.
- Use an interactive prototype to test navigation, disclosure, focus, feedback, and task completion.
- Use production code when platform behavior, realistic data, responsiveness, or performance is the risk.

Do not polish a broad fake product when one critical path or component can answer the question.

## Sketch structure before production code

For a new page or substantial redesign, write a content outline or ASCII wireframe before components. Show:

- regions in reading and task order;
- the purpose and real content of each region;
- the dominant action or evidence;
- what changes across narrow and wide layouts;
- the element that could only belong to this product.

Do not begin with a memorized sequence such as hero → logo strip → feature cards → three steps → testimonials → pricing → FAQ → final CTA. Include only regions supported by the brief. Review the inexpensive structure before polishing it.

## Risk-first loop

1. State the hypothesis.
2. Identify the user, task, content, and success signal.
3. Build only what is necessary for a realistic test.
4. Test the uncertain or expensive part first.
5. Observe behavior and failure, not preference alone.
6. Decide to keep, change, or discard.
7. Transfer validated decisions into the production system; do not treat prototype shortcuts as architecture.

## Evaluate alternatives fairly

Use the same content and task across alternatives. Avoid letting one direction win because it received better copy or more polish. Compare:

- comprehension and task success;
- perceived hierarchy;
- errors and hesitation;
- fit with brand and audience;
- implementation and maintenance cost;
- behavior at representative sizes.

Prototype output is evidence, not permission to expand the product scope.
